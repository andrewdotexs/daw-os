## Parte 1 — Il rapporto in bozza e due letture

### Parte 1: che cosa si fa e perché

Il [rapporto](../../misure/fase-0/rapporto.md) raccoglie in un posto solo ciò che la fase ha misurato: l'esito sui quattro criteri, le impronte della configurazione, l'istogramma delle 24 ore, la classificazione dei sei risvegli sopra i 20 µs, gli esperimenti, i limiti della misura e ciò che resta aperto. Non contiene numeri nuovi: tutto viene dalle guide dei passi e dai dati grezzi.

Due letture brevi lo completano. Si fanno adesso perché la macchina è ancora nella configurazione misurata.

- **`dawos-hwnoise` per dieci minuti** (A-40). Nell'accettazione di P0.6e, a 95 W, il package era a 51 °C; nelle misure precedenti, alla stessa potenza, a 65 °C. La campagna ha escluso l'ora del giorno. Una misura in più, a macchina calda e di giorno, dice quale dei due valori si ripete. Dice anche se le letture tornano ogni 5 secondi esatti, come nell'ultima misura e mai prima.
- **Una ricerca nel registro del kernel** (A-43). Il processore sa segnalare le operazioni che bloccano il bus della memoria per tutti i core, e il kernel le annota. Il filtro dello script della campagna non raccoglieva quelle righe. Se ci sono, uno dei due candidati per le pause di 18 µs diventa concreto; se non ci sono, si indebolisce.

### Parte 1: comandi

Sul PC di sviluppo, con `H=INDIRIZZO`.

```bash
cd ~/daw-os && git pull --rebase origin claude/affectionate-faraday-5le4g4
```

**1. Il registro del kernel**: prima le righe sul blocco del bus, poi gli ultimi avvisi di qualunque tipo, tolte le cadute del collegamento.

```bash
ssh "root@${H}" 'journalctl -k -b --no-pager | grep -i -E "split.?lock|bus.?lock" | head -n 20; echo "---- avvisi"; journalctl -k -b --no-pager -p warning | grep -v "NIC Link is" | tail -n 30; echo "---- accesa da $(cut -d. -f1 /proc/uptime) s"'
```

**2. Il rumore hardware**, dieci minuti e mezzo:

```bash
ssh "root@${H}" 'dawos-hwnoise 10m dopo-campagna > /dev/null; sleep 625; dawos-hwnoise --status | tail -n 14'
```

**3. I dati nel repository**:

```bash
make measure-fetch HOST="${H}" && git add docs/misure && git commit -m "Phase 0 measurements: hardware noise after the campaign" && git push
```

### Parte 1: che cosa mi aspetto

| Lettura | Attesa |
| --- | --- |
| Righe sul blocco del bus | Una riga dell'avvio che dice in che modo il kernel le tratta. Se ce ne sono altre, con il nome `stress-ng`, è un risultato _(da verificare: non so se ci sono)_. |
| Altri avvisi | Nessuno che non conosciamo già. |
| Rumore hardware | Nessun buco di almeno 1 µs, nessun SMI, circa 95 W. |
| Temperatura | È la domanda: 51 °C o 65 °C. Non ho una previsione. |
| Letture in dieci minuti | 120, se la spiegazione che ho proposto per A-40 (il kernel 6.18.64) è giusta _(da verificare)_. |

### Parte 1: che cosa verificare

1. Il rapporto: leggilo, e dimmi che cosa manca o non torna. È il documento che resta della fase.
2. Il 285K è acceso senza interruzioni dall'inizio della campagna: i secondi stampati dal primo comando sono più di 140 000.
3. `make measure-fetch` non segnala indirizzi.

- L'uscita di `make measure-fetch` e del `git push`.
