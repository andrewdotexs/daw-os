# P0.6b — Misure termiche, _fair server_, frequenza e stati di riposo dei core live

- **Macchine**: 285K per le misure; PC di sviluppo per costruire gli strumenti delle parti 2, 3 e 4.
- **Prerequisito**: P0.6a superato.
- **Stato**: in corso dal 16 novembre 2026. Consegnata la parte 1, che usa strumenti già nell'immagine.
- **Accettazione**: curva termica e limite di potenza riverificati con le ventole collegate correttamente; rischio del _fair server_ spento misurato (E-02) e rischio K-04 chiuso o riaperto con i numeri; frequenza dei core live fissata a un valore che regge a pieno carico entro il limite di potenza; stato di riposo dei core live scelto sui numeri (E-01, ADR 0009).

## Come è diviso

Quattro parti, ognuna con la sua consegna e le sue misure. L'ordine conta: ogni parte usa ciò che la precedente ha stabilito.

| Parte | Che cosa | Perché in questo punto | Strumenti |
| --- | --- | --- | --- |
| 1 | Curva termica e verifica del limite a 160 W | Le ventole del radiatore sono state ricollegate il 16 novembre: i numeri del passo P0.4b non descrivono più la macchina. Tutto il resto dipende da questi. | Già nell'immagine. |
| 2 | E-02: un thread real-time che non si ferma mai su un core live, con il _fair server_ spento e acceso | È il rischio della scelta fatta in P0.6a; non dipende dal raffreddamento ma va chiuso presto. | Da consegnare. |
| 3 | Frequenza dei core live: quanto oltre 3,7 GHz regge con tutti gli altri core a pieno carico | Usa la curva della parte 1. | Da consegnare. |
| 4 | E-01: stati di riposo dei core live (attesa attiva, C1, C1E) | Richiede di cambiare il firmware, che sposta consumi e temperature: per ultima, così non altera le altre misure. | Da consegnare. |

## Parte 1 — Misure termiche

### Che cosa si misura e perché

La curva del passo P0.4b («tanti watt, tanti gradi») e la verifica del limite a 160 W sono state fatte con una delle due ventole del radiatore collegata a un connettore sbagliato: partiva in ritardo. Ora che è collegata bene ci aspettiamo temperature **uguali o più basse**. Se fossero più alte, qualcosa è cambiato in peggio e ci si ferma.

Valori di allora (14 novembre 2026, stanza a 24 °C), con cui confrontare:

| Limite | Temperatura a fine gradino |
| --- | --- |
| 60 W | 48–54 °C |
| 80 W | 58–61 °C |
| 100 W | 63–66 °C |
| 125 W | 71–72 °C |
| 150 W | 76–80 °C |
| 160 W, dieci minuti | 83,3 °C (massimo 88 °C) |

### Scelte tecniche

- **Si misura con il profilo `generic`.** Con il profilo `285k` i processi di carico non possono usare i core live, che resterebbero fermi: la curva non sarebbe confrontabile con quella di allora. `dawos-profile --try generic` vale per un solo avvio; al riavvio successivo torna `285k`.
- **Il gradino più alto è 160 W.** Lo strumento può solo abbassare il limite sotto quello del firmware, che ora è 160 W. Il gradino a 175 W di allora non si può ripetere, e non serve.
- **Nessun file nuovo**: `dawos-thermal-sweep` è nell'immagine dal passo P0.5a.

### Comandi

Sul PC di sviluppo, una volta per terminale:

```bash
H=INDIRIZZO
```

Annota la temperatura della stanza. Poi riavvia senza isolamento, per questa volta:

```bash
ssh "root@${H}" 'dawos-profile --try generic && systemctl reboot'
```

```bash
make remote-test HOST="${H}"
```

Atteso: `PASS`, con `profile=generic tune=off`.

La curva, sei gradini da cinque minuti:

```bash
ssh "root@${H}" dawos-thermal-sweep --label ventole 60 80 100 125 150 160
```

Dura 32 minuti. Se serve fermarla: `ssh "root@${H}" systemctl stop dawos-thermal-sweep` (i limiti tornano a 160 W).

```bash
ssh "root@${H}" dawos-thermal-sweep --status
```

Atteso alla fine: una tabella con sei righe, `smi` a 0 e nessuna nota di arresto anticipato.

Poi la verifica del limite, dieci minuti a 160 W:

```bash
ssh "root@${H}" dawos-thermal-sweep --step 600 --label limite 160
```

Dopo dodici minuti:

```bash
ssh "root@${H}" dawos-thermal-sweep --status
```

Atteso: `temp_end_c` non sopra 85 °C con la stanza a 25 °C, che è il criterio del passo P0.4b.

Infine si torna al profilo isolato e si archivia:

```bash
ssh "root@${H}" systemctl reboot
```

```bash
make remote-test HOST="${H}" PROFILE=285k
```

```bash
make measure-fetch HOST="${H}" && git add docs/misure && git commit -m "Phase 0 measurements: thermal curve and limit check with both radiator fans" && git push
```

### Cosa ho verificato io

Nulla di nuovo da verificare in QEMU: la parte 1 non cambia l'immagine. Ho controllato nello strumento che il gradino a 160 W sia ammesso con il firmware a 160 W e che un gradino più alto non lo sia.

### Da verificare sul 285K

| Punto | Che cosa potrebbe andare diversamente | Dove si vede |
| --- | --- | --- |
| `--try generic` con un profilo fissato | Parte comunque `285k` | `make remote-test` dà `FAIL` su `profile=generic`. |
| Temperature rispetto al 14 novembre | Più alte invece che uguali o più basse | Tabella della curva. |
| Ritorno a `285k` al riavvio successivo | Resta `generic` | L'ultimo `make remote-test`. |

### Cosa incollarmi

1. La temperatura della stanza.
2. L'uscita dei due `dawos-thermal-sweep --status`.
3. L'uscita dei due `make remote-test`.
